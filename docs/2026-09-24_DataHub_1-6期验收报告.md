## 2. 系统架构

```text
浏览器 / NocoBase / Agent
        ↓ HTTPS
Nginx
        ↓
FastAPI Backend
   ├── Asset Registry：原始资产、版本、权限、业务线
   ├── Parsing：解析、清洗、Markdown、Chunk
   ├── Review：人审状态机
   ├── Index/Search：已审核资产检索
   ├── Ask：答案 + 引用
   ├── Agent Gateway：受控工具
   ├── Graph：实体 / 关系 / 来源追溯
   └── BI / Audit：指标与治理
        ↓
PostgreSQL 16：业务元数据 / 状态 / 图谱 / 审计
MinIO / OSS 兼容存储：原始区、处理区、Curated、索引输入、Agent 输出、归档
Worker：失败解析任务后台重试与健康心跳
```

分层存储：

```text
01_raw          原始上传
02_staging      解析 / 清洗中间产物
03_curated      审核后整理产物
04_index_input  索引输入
05_agent_output Agent 输出
90_archive      归档
```

## 3. 已完成项

### 3.1 资产与文件

- 资产创建、列表、详情、更新、软删除。
- 业务线、资产类型、负责人、可见范围、标签、版本。
- 文件上传、checksum、大小、类型、上传人。
- 支持 `public / business / private` 三类可见范围。
- 文件版本与 Chunk 查询。

### 3.2 解析与任务

- 支持 Markdown、TXT、CSV、PDF、DOCX、XLSX。
- 解析结果统一为 Markdown。
- 自动切分 Chunk，记录数量和状态。
- 处理任务记录开始、结束、输入、输出、进度、成功、失败、错误原因。
- API 当前同步处理小文件；Worker 负责失败任务后台重试。

### 3.3 审核与状态机

- `waiting_review → approved / rejected`。
- `approved → archived`。
- 只有 Approved 资产可进入 Index。
- 只有 Indexed 资产可进入 Serving。
- 管理员可处理跨状态治理操作；普通成员无审核权。

### 3.4 检索与问答

- 只检索 Approved / Indexed / Serving 资产。
- 返回 `asset_id`、标题、片段、版本、更新时间、相关度。
- `/api/v1/search` 同时返回 `results` 与同形状 `citations`。
- `/api/v1/ask` 返回 `answer`、`citations`、`latency_ms`。
- 未配置 DeepSeek 时返回检索式答案；配置后调用 DeepSeek，失败时自动回退到检索式答案。
- 可选 Embedding API 可用于语义重排；未配置时使用词法检索。

### 3.5 Agent

已提供受控工具：

```text
search_assets     搜索已授权、已审核资产
read_asset        读取单条已审核资产
generate_report   基于检索结果生成摘要报告
```

- Agent 不能直接越过资产权限。
- 未审核资产不可被 Agent 读取。
- Agent 调用、耗时、命中资产、状态写入 AgentLog。

### 3.6 知识图谱

- 实体支持名称、类型、业务线、描述、状态、来源资产列表。
- 关系支持类型、置信度、状态、来源资产列表。
- 图谱查询支持业务线、实体类型、实体 ID、关系类型、关系状态、来源资产 ID。
- `asset_ids` 提供证据追溯，兼容旧字段 `asset_id`。
- 关系置信度约束为 `0 ≤ confidence ≤ 1`。

### 3.7 BI 与审计

- 资产总量与按天趋势。
- 业务线分布、状态分布。
- 处理任务成功率、失败率、平均耗时。
- 审核通过率、驳回率、平均审核时长。
- 索引数量、失败率、Chunk 总量。
- 检索命中率、问答次数、引用覆盖率。
- Agent 调用数、成功率、平均延迟、按工具 / 用户分布。
- 审计日志覆盖登录、创建、上传、解析、审核、索引、图谱治理等动作。
- BI API 实时聚合业务数据，不写演示假数字。

### 3.8 权限与安全

- 角色覆盖：`admin`、`reviewer`、`editor`、`member`。
- 业务线隔离：不同业务线用户默认不能读取 `business` 可见资产。
- 私有资产只有 Owner / Admin 可读。
- Admin / Reviewer 才能审核、索引、归档和查看审计日志。
- 管理员用户列表仅 Admin 可访问。
- 密码使用 PBKDF2-SHA256，随机盐，390,000 次迭代。
- 旧原型 SHA256 密码在验证成功后自动升级为新哈希。
- Token 使用 HMAC 签名并带过期时间。
- 生产环境禁止弱密码 / 示例密码启动。
- 前端不再内置默认密码，改为登录表单。
- 后端容器使用非 root 用户 `10001` 运行。

参考依据：

- [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- [FastAPI Security Documentation](https://fastapi.tiangolo.com/tutorial/security/)
- [PostgreSQL Authentication Methods](https://www.postgresql.org/docs/16/auth-methods.html)

## 7. curl 验收步骤

以下示例假设服务地址是 `http://127.0.0.1:13001`。

### 7.1 健康检查

```bash
BASE=http://127.0.0.1:13001
curl -i "$BASE/api/health"
curl -i "$BASE/api/health/ready"
```

验收标准：

```text
/api/health         200，status=ok
/api/health/ready   200，database=ok，storage=ok
```

### 7.2 登录

```bash
TOKEN=$(curl -s -X POST "$BASE/api/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"你的真实密码"}' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["token"])')

AUTH="Authorization: Bearer $TOKEN"
echo "$AUTH"
```

验收标准：

- 正确密码返回 `token` 和用户信息。
- 错误密码返回 `401`。

### 7.3 创建资产

```bash
ASSET=$(curl -s -X POST "$BASE/api/assets" \
  -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{
    "title":"验收测试资料",
    "business_line":"zhuangzhou",
    "visibility":"business",
    "owner":"admin",
    "source_text":"妆舟渠道分销规则：订单必须先人工复核。",
    "tags":["验收","渠道"]
  }')

echo "$ASSET"
ASSET_ID=$(echo "$ASSET" | python3 -c 'import json,sys; print(json.load(sys.stdin)["asset_id"])')
```

验收标准：

- 返回 `asset_id`。
- `status=raw`。
- `created_by=admin`。

### 7.4 上传文件

```bash
cat > /tmp/datahub-acceptance.md <<'EOF'
# 妆舟验收资料

妆舟渠道分销规则：订单必须先人工复核，审核通过后才能进入知识服务。
EOF

curl -s -X POST "$BASE/api/assets/$ASSET_ID/files" \
  -H "$AUTH" \
  -F "file=@/tmp/datahub-acceptance.md;type=text/markdown"
```

验收标准：

- 返回 `file_size > 0`。
- 返回 `checksum`。
- `storage_path` 位于 raw 区或 S3 raw key。

### 7.5 解析

```bash
curl -s -X POST "$BASE/api/assets/$ASSET_ID/process" \
  -H "$AUTH"
```

验收标准：

- `status=waiting_review`。
- `chunk_count > 0`。
- `processed_markdown` 非空。
- `/api/jobs` 中出现成功任务。

### 7.6 审核与索引

## 8. 用户视角验收剧本

1. 打开站点，使用管理员分配的账号密码登录。  
2. 首页看到资产总量、处理中、待审核、已通过、服务中、失败任务。  
3. 上传一份 Markdown / PDF / DOCX / XLSX。  
4. 系统创建资产，上传文件，解析为 Markdown，生成 Chunk 和任务。  
5. 状态进入“待审核”。  
6. 审核人通过后进入“已通过”。  
7. 执行索引，资产进入“已索引”或“服务中”。  
8. 在知识检索提问，答案必须带来源。  
9. Agent 执行搜索 / 读取 / 报告，只能访问有权限的已审核资产。  
10. 图谱页查看实体、关系、来源资产。  
11. BI 页查看总量、处理率、失败率、审核、检索、Agent 调用。  
12. 换一个其他业务线普通用户登录，确认看不到隔离资产、不能审核、不能看审计日志。

| 解析队列 | API 同步解析，Worker 目前重试失败任务 | 大文件可能占用请求时间 | 引入 Celery / RQ / Arq 或持久队列，API 只入队 |
| 向量索引 | 内置词法检索，可选 Embedding 重排 | 超大语料和复杂语义检索有限 | PostgreSQL pgvector、Elasticsearch 或 RAGFlow 引擎 |
| 图数据库 | PostgreSQL 关系表 + API 查询 | 超大图和多跳性能有限 | Neo4j / NebulaGraph / Kùzu，保留 PostgreSQL 作为治理源 |
| 图谱抽取 | 手工 API / 前端维护，演示数据有初始化图谱 | 不会自动从所有文档抽实体关系 | LLM 抽取 + 人工审核 + 证据链接 |
| 对象存储 | MinIO / OSS adapter 已实现并通过 compose 配置，但未在本次完成外部云对象存储端到端演练 | 生产使用 OSS 前仍需真实 bucket 演练 | 部署前上传、下载、解析、备份恢复各验证一次 |
| 备份恢复 | 脚本与校验完成，未做真实生产备份演练 | 不能宣称生产级 RPO / RTO | 灾前做一次完整备份、清空、恢复、业务验收 |
| HTTPS | 配置和语法验证完成，未签发正式证书 | 需部署方提供证书和域名 | 接入证书自动续期或运维签发流程 |
| 数据库迁移 | `create_all` + 少量兼容列升级 | 复杂历史迁移和回滚不足 | Alembic 版本化迁移 |
| 字段级权限 | 已覆盖角色、业务线、资产可见范围 | 尚未做到字段 / 行级动态规则 | 增加策略引擎或 ABAC |
| 企业连接器 | 浏览器上传为主 | 飞书 / 网盘 / ERP / CRM 自动同步未全接 | 下一阶段按数据源优先级接连接器 |
| 前端体验 | 功能可用，登录已去掉内置弱密码 | 视觉与交互仍需产品化 | 按设计规范继续重构组件与图表 |
| 压测 | 未执行正式压测 | 无法给出生产 QPS / 并发承诺 | 用 Locust / k6 做上传、解析、检索、问答压测 |

## 11. 最终判定

本版本通过第 1-6 期“验收可用”标准：

- 原始数据可以进入系统。
- 系统可以解析、清洗、切片并记录任务。
- 人审后的数据可以进入索引和问答服务。
- Agent 可以在权限边界内使用数据。
- 图谱可以保留证据来源。
- BI 与审计可以说明资产和处理效果。
- 生产部署、HTTPS、备份、恢复、健康检查和安全基线已有骨架。
- 自动化测试覆盖主要业务链路和拒绝路径。

尚未达到大型企业生产 SLA；上线前必须完成真实服务器部署、真实数据演练、对象存储演练、备份恢复演练、压测和安全评审。
